# 字間：架站方案研究與第一版設計

> 本文保留第一版架構研究；現行功能與部署以 README.md 及「模式規劃與Google收錄.md」為準。

查核日期：2026-10-29。需求：能讓 Google 搜尋的中英文打字練習網站；目前只在本地開發，不 push、不部署。

## 建議採純靜態網站，之後部署 GitHub Pages

GitHub repository 是放程式碼的地方；真正讓訪客用網址瀏覽的是 GitHub Pages。GitHub Pages 可以直接發佈 HTML、CSS、JavaScript，也可執行建置流程。個人專案網址通常是 `https://<owner>.github.io/<repositoryname>/`，也可綁定自己的網域。GitHub Free 支援公開 repository 的 Pages。

這個專案的題庫、倒數、中文組字、字元比對與成績計算都能在訪客瀏覽器完成。因此現階段不需要伺服器或資料庫。我建議先保留簡單的靜態架構，把練習流程做好，再決定是否擴充。

官方來源：[What is GitHub Pages?](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

### 為什麼第一版不導入大型框架

本案主要是單一測驗狀態與四種題目模式，不需要伺服器渲染的會員頁或複雜資料存取。因此實作採原生 HTML、CSS、ES modules，Node.js 只負責本機預覽與產出靜態頁面，不是正式網站的後台。

沒有 npm 執行期依賴，也無須維護前端框架的套件更新。初始 HTML 就包含頁面介紹、標題、模式導覽、文章來源與題目文字，計分互動由 JavaScript 接手。這是針對目前規模的選擇；未來功能變多仍可逐步重構。

### 這個選擇的界線

| 功能 | 純靜態第一版 |
| --- | --- |
| 打字、倒數、即時速度、錯字比對 | 可完整實作 |
| 各模式可搜尋的公開頁面 | 可建立靜態 HTML |
| 同一瀏覽器的歷史紀錄 | localStorage 可處理 |
| 跨裝置帳號與同步 | 需另外的身份與資料服務 |
| 可被信任的公開排行榜 | 需伺服器驗證與防作弊，單靠前端不足 |
| 訪客即時選擇任意 Wikipedia 條目 | 可再研究 API；第一版先用檢閱過的固定節錄 |

GitHub Pages 目前的公開站點大小上限是 1 GB，頻寬有每月 100 GB 軟性限制，並有其他使用限制；這個小型文字工具的初期資料量遠低於該範圍。若之後走向收費服務，須重新檢查 Pages 對商業 SaaS 的限制與適合的託管方案。

官方來源：[GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## Google 搜尋：主機只是其中一環

Google 會抓取、渲染並建立索引；官方仍建議預先產生或伺服器產生 HTML，因為對訪客與爬蟲較快，且其他搜尋引擎未必執行 JavaScript。

第一版採五個實體頁面：首頁、`/zh/words/`、`/zh/articles/`、`/en/words/`、`/en/articles/`。各模式有對應的標題、meta description、介紹與一般 `<a>` 導覽。頁面可直接開啟與重新整理，不需要 GitHub Pages 額外支援單頁應用的路由回退。

正式網址確認後，建置流程會產生 canonical 與 sitemap；首頁 canonical 與中文單字頁合併。預設不填 localhost、虛構網域或尚未確定的 GitHub 網址。`robots.txt` 允許抓取，也不把練習紀錄輸出成公開頁面。

官方來源：[Google JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)

上線後應驗證 Search Console 網站所有權、提交 sitemap，並用網址檢查工具確認 Google 能讀取頁面。sitemap 幫助發現網頁，但不保證收錄、收錄時間或排名。網站還需要清楚的原創用途、良好體驗與持續維護，才有機會累積自然搜尋流量。

官方來源：[Google crawling and indexing FAQ](https://developers.google.com/search/help/crawling-index-faq)、[Sitemaps overview](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)

## 維基百科文章：隨網站打包，保留版本與署名

在開發時透過 Wikimedia API 取回文章導言，選擇茶、自行車、圖書館等熟悉的主題；中文採臺灣繁體轉換。段落在本地節錄並與網站一起發佈，所以練習時不依賴 Wikipedia 的連線、API 限額或文章即時變更。

Wikimedia 重用規則允許以原文章連結署名，因為頁面歷史列出作者；修改或節錄須遵守適用授權、標示更動。本站每篇保留原文、永久版本、編輯歷史、取得日期與 CC BY-SA 4.0 連結，節錄文字沿用相同授權。題庫中的 `revision` 可對回當時取用的文章，而非只連到持續變動的最新版。

官方來源：[Wikimedia Terms of Use §7](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use/en#7._Licensing_of_Content)

中文組字使用 `compositionstart`、`compositionend` 與 `KeyboardEvent.isComposing` 判別，避免候選字的 Enter 被當成送出。由於瀏覽器與實際輸入法的事件順序可能不同，除了事件模擬測試，還需要用使用者慣用輸入法實際操作。

技術參考：[MDN compositionend](https://developer.mozilla.org/en-US/docs/Web/API/Element/compositionend_event)

## 視覺與使用細節

暫定名稱「字間」：取字與字之間的停頓與節奏。暖白紙感、墨綠色功能區、朱紅色當前題目，搭配宋體文字與等寬數字。主畫面直接放語言、模式、時間與練習框，不需要先經過登入或冗長首頁。

第一個字才計時，讓使用者先確認輸入法。單字十題預覽、每題送出後補上新題；文章按句進行，讓中文使用者能自然確認選字、也保留標點練習。錯誤可以送出，測驗結束才集中檢視，讓練習不中斷。

第一版已實作完整流程，接著最值得使用者實測的是：視覺風格、單字難度、文章逐句送出的手感，以及分數呈現方式。這些確認後再設定正式名稱、網址、公開授權與 GitHub Pages 發佈。
